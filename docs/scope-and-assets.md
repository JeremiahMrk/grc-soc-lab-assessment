# Scope and Assets

## Assessment Object

The assessment covers a personal Automated SOC Home Lab used for security monitoring, detection, alert enrichment, and incident-analysis exercises.

The ISMS boundary was intentionally limited to the lab environment rather than the candidate's full personal device ecosystem.

## In-Scope Categories

The final asset registry contains 24 in-scope assets covering categories such as:

- Ubuntu server and Windows endpoint
- Wazuh Manager, Indexer, Dashboard, and Agent
- Sysmon telemetry
- n8n workflow automation
- Docker runtime
- custom detection rules and security configuration
- security-event data stores
- lab network segment
- administrative and service identities

## External / Supporting Dependencies

Four dependencies/supporting components are recorded separately from the in-scope asset registry, including external threat-intelligence / notification services and supporting infrastructure.

The separation between in-scope assets and dependencies is deliberate: third-party services can be relevant to risk without being treated as internally auditable assets.

## Asset Metadata

The full private register records attributes including:

- asset identifier
- category
- version / technical detail
- function
- data classification
- criticality
- scope status

## Public-Disclosure Note

The public portfolio intentionally omits unnecessary IP addresses, credentials, account identifiers, and low-level configuration details. These details are not needed to demonstrate the GRC methodology and would add avoidable security exposure.
